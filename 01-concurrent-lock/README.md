# 01 并发计数

对比多线程环境下四种计数方案的差异。

## 背景

多个线程同时对同一个变量做自增时，`count++` 在机器指令层面并不是一个原子操作。
它实际由三条指令组成：

1. 从内存读取 `count` 到寄存器
2. 寄存器加一
3. 把寄存器写回内存

线程切换可能发生在第 1 步和第 3 步之间。此时两个线程读到的是同一个旧值，
各自加一后写回，结果只增加了 1 而不是 2。这个现象叫**竞态条件**（race condition），
最终计数会小于理论值。

## 四种方案

| 方案 | 实现 | 拿不到锁时的行为 | 适用场景 |
|---|---|---|---|
| 无锁直接自增 | `(*pcount)++` | —— | 仅用于演示错误结果 |
| 互斥锁 | `pthread_mutex_lock` | 线程休眠，让出 CPU | 临界区长、竞争激烈 |
| 自旋锁 | `pthread_spin_lock` | 线程忙等，一直占用 CPU | 临界区极短，避免切换开销 |
| CPU 原子指令 | `lock; xaddl` | 无锁，单条指令完成读改写 | 单个变量的简单操作 |

## 编译与运行

```bash
gcc lock.c -o bin/lock -lpthread
./bin/lock
```

程序启动 10 个线程，每个线程尝试自增 100000 次，主线程每秒打印一次当前计数。

原始版本中 `inc()` 的实现：

```c
int inc(int *value, int add) {
    int old;
    __asm__ volatile(
        "lock; xaddl %2, %1;"      // lock 前缀保证该指令在多核下原子执行
        : "=a" (old)                // 输出：旧值放入 eax
        : "m" (*value), "a"(add)    // 输入：内存操作数、加数放入 eax
        : "cc", "memory"            // 会修改标志寄存器和内存，通知编译器不要重排
    );
    return old;
}
```

`xaddl` 的语义是"交换后相加"：把寄存器值和内存值交换，然后把两者之和写回内存。
加上 `lock` 前缀后，整条指令在执行期间锁定缓存行，其他核心无法同时访问，
从而消除了竞态。
